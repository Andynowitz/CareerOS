# CareerOS API

Base URL:

```text
http://localhost:8000
```

## OpenAPI

FastAPI automatically exposes:

* `/docs` — Swagger UI
* `/redoc` — ReDoc
* `/openapi.json` — OpenAPI specification

The API is versioned under:

```text
/api/v1/
```

---

## Phase 1 Endpoints

### GET `/health`

Public service health check.

Response:

```json
{
  "status": "ok"
}
```

### GET `/api/v1/health`

Public API health check.

Response:

```json
{
  "status": "ok",
  "service": "careeros-api"
}
```

### GET `/api/v1/db-check`

Checks connectivity to PostgreSQL.

A successful response indicates that the FastAPI application can establish a database connection and execute a query.

### GET `/api/v1/auth/status`

Returns the currently authenticated user.

Authentication is managed by Better Auth in the Next.js application. FastAPI validates the Better Auth session against the shared PostgreSQL session store.

A valid authenticated request returns:

```json
{
  "id": "user-id",
  "email": "user@example.com",
  "name": "User Name"
}
```

Unauthenticated requests return:

```http
401 Unauthorized
```

Possible responses include:

```json
{
  "detail": "Authentication required"
}
```

or:

```json
{
  "detail": "Invalid session"
}
```

or:

```json
{
  "detail": "Session expired"
}
```

## Authentication Architecture

Better Auth is the single authentication authority.

The authentication flow is:

```text
Browser
   │
   ▼
Next.js / Better Auth
   │
   │ creates session
   ▼
PostgreSQL
   │
   │ session token
   ▼
FastAPI
   │
   │ validates session
   ▼
Authenticated user
```

FastAPI does not maintain a separate password or authentication system.

Protected API endpoints should use the shared authentication dependency:

```python
Depends(get_current_user)
```

This provides the authenticated user context to API endpoints.

Authorization and resource ownership checks remain the responsibility of the backend.

## API Design Principles

The API follows these principles:

* Versioned endpoints under `/api/v1/`
* Authentication handled by Better Auth
* Authorization handled by the backend
* Request validation at API boundaries
* Database access through SQLAlchemy
* Business logic separated from route handlers
* Environment-driven configuration
* Explicit HTTP status codes
* OpenAPI documentation generated by FastAPI
